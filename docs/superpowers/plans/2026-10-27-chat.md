# Human messaging implementation plan

**Goal:** Reusable human chat with a provider, hooks and composable components.
**Architecture:** Provider-owned state and pure transitions; application callbacks own transport. No SDK, socket or persistence is imposed. Public exports belong to the main package, independently of AI.
**Tech stack:** Existing React 19, TypeScript, theme tokens, Avatar, Button and UiIcon.
**Spec:** User requested human messaging and explicitly required context and a provider. The implementation choices below are ours.

## Contract

- `ChatProvider` owns conversations, messages, per-conversation drafts, replies, unread counts, typing and history loading. `useChatState`, `useChatActions`, `useChatConversation` and `useChat` expose it.
- `onSendMessage` receives a message with a stable client identifier. An optimistic message becomes sent on success, or remains visible with an error and retry. New drafts and other conversations survive late completions. Echoes reconcile with acknowledgements; status cannot regress after a read receipt.
- `receiveMessages`, `updateConversation` and `setTyping` integrate application events. `onLoadOlderMessages` loads history explicitly and preserves scroll position. Switching current-user identity resets provider state.
- Components: conversation list, header, message, scrollable message list, composer and responsive workspace. They consume the same provider and can be arranged separately.
- Plain text, keyboard/IME support, reply preview, per-message delivery state, unread counts, empty/error states and mobile back navigation. Reuse current themes and icon slots. No attachments, voice, editing, server, storage or network protocol in this first slice.

## Tasks

- [x] Implement types, pure state transitions and provider actions; validate async failure, retry, concurrent sends, echoes and account changes in a real browser.
- [x] Build composed UI and interactive Ladle stories; check mobile, dark themes, keyboard, history anchoring and scrolling away from new messages.
- [x] Document integration and exports; run all unit tests, build, typecheck, theme/icon checks and focused browser verification.

## Rulings

- Work in the current clean checkout, matching the user's request to start immediately after the merge. No additional worktree or dependencies.
- Maintain text drafts while switching conversations. Clear a submitted draft immediately; failed content stays in the message with a retry action, so a newly typed draft cannot be overwritten.
- Use the existing visual system. This is an addition to the component library, not a new visual identity.


## Resultado de ejecución — 27 de octubre de 2026

Implementadas las tres fases en la rama existente. Incluye las revisiones solicitadas durante la construcción: compositor integrado, notas de voz con onda y controles propios, separación entre conversaciones, iconos por tipo de archivo y foco sin marco duplicado en los temas monocromos.

Validación: 71 pruebas unitarias, tipos, compilación, los dos flujos de navegador del chat, regresiones de voz de IA e iconos y controles de colores/iconos. Se revisaron escritorio, móvil, seis temas, zoom al 200 % y movimiento reducido. Los fallos encontrados en revisión de concurrencia se corrigieron y se probaron.

Publicación autorizada por el usuario: versión 0.5.0, integración en dev y main, subida a Git y npm. La aplicación sigue aportando transporte y persistencia mediante callbacks.
