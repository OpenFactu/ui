Guard scripts (run after touching colors, tokens or controls):

```bash

node scripts/check-nativos.mjs            # no native <select>, <textarea>, input[type=date] outside their wrapper components
node scripts/check-icons.mjs              # no direct icon-library imports outside src/icons/lucide.ts
node scripts/check-i18n.mjs               # no hand-written UI text in src/ outside src/i18n/catalog (npm run check:i18n)
node scripts/check-motion.mjs             # every CSS/inline duration and delay multiplies by --k-motion (npm run check:motion)
node scripts/check-theme-scale.mjs        # font sizes scale with --k-text-scale, 1px borders use --k-border-width (npm run check:theme-scale)
npm run check                             # every guard above plus check-tokens (also runs in CI and before publishing)
npm run check:a11y                        # axe over every story against scripts/a11y-baseline.json; needs Ladle (--update to accept)
npm run check:contrast                    # check-contrast.mts over its story list; needs Ladle
npx tsx scripts/check-tokens.mjs          # styles/tokens.css must match resolveTheme() output
npx tsx scripts/check-contrast.mts [preset-id]   # real WCAG contrast of story text; needs Ladle running
npm run shots -- .shots/base              # screenshot every story light+dark; then
node scripts/shots.mjs --diff .shots/base .shots/after
```

Browser scripts use `playwright-core` with system Chrome (`C:/Program Files/Google/Chrome/Application/chrome.exe`); override with `CHROME_PATH` and `LADLE_URL`. Restart Ladle after adding new story files. For cross-cutting visual changes, take a `shots` baseline before editing and diff afterwards.

New probes should use `scripts/probe-kit.cjs` (`run`, `storyUrl`, `createChecker`, `touch`/`flick`, `CHROME`/`BASE` from env); it works from `.cjs`, `.mjs` and `.mts`. `npm test` runs every `scripts/*.test.cjs`; `test-support.cjs` also exports `render()` (SSR markup) and `near()`.

Unit tests load TS sources directly (no build) via `scripts/test-support.cjs`, which registers a `ts.transpileModule` require hook — require `../src/...ts` paths from tests.

## Architecture

**Entry points** (`package.json` `exports`): `.` → `src/index.ts` (components, hooks, contexts, theme); `./charts` → `src/charts` (only place that imports `recharts`, an optional peer dep — never import it from the main entry); `./ai` → `src/ai` (provider-agnostic chat/AI UI, no SDK or network); `./qr` → `src/qr` (only place that imports `uqr`, optional peer dep; `matrix.ts` is pure path/SVG generation, readability checked with jsQR in `scripts/qr.test.cjs` and `scripts/probe-qr.cjs` — rerun both after touching module/eye shapes); plus raw CSS (`styles/*.css`) and `tailwind/preset.cjs`. New public modules must be re-exported from the relevant `index.ts`.

**Styling contract.** Components are Tailwind classes that reference CSS variables, compiled by the *consumer's* Tailwind JIT (the consumer scans `node_modules/@openfactu/ui/dist`). Therefore:
- Class names must be literal strings (use maps of full class strings, never `bg-${x}`).
- Every `var()` carries a fallback: `bg-[var(--bg-card,#ffffff)]`.
- Component-specific CSS that can't be utilities lives in `styles/*.css` (e.g. `code-editor.css`, `ai.css`) and is pulled in by `styles/index.css`.

**Token layers.** `--k-ink-*`, `--k-line*`, `--k-surface` are a *fixed palette* (same in light/dark). Components must target the *semantic layer* that responds to mode: `--bg-*`, `--fg-*` (`--fg-default`/`body`/`muted`/`subtle`), `--border-*`. Status colors: `--k-danger` for fills, `--k-danger-fg` for text.

**Theme engine** (`src/theme`). A theme is essentially two colors + mode (+ radius, typography); `derive.ts` computes hovers, contrasting foregrounds, dark surfaces and accent scale; `tokens.ts` `resolveTheme()` is pure and `themeToCssVars/themeToCssText` serialize it; `applyTheme.ts` writes vars onto `<html>` (or a subtree) and toggles `.dark`. `styles/tokens.css` is a hand-maintained copy of the default resolved theme — any change to `derive.ts`/`tokens.ts` defaults must be mirrored there (verify with `check-tokens`). `ThemeProvider` is optional: components never read theme context, only CSS variables.

**Material, density, motion, text scale.** The theme also carries `material` (blur/alpha/saturate/border/highlight), `backdrop`, `density`, `motion` and `typography.scale`, emitted as `--k-surface-*`, `--k-app-backdrop`, `--k-density`, `--k-motion`, `--k-ease`, `--k-text-scale` (defaults mirrored in `styles/tokens.css`). Glass only activates through `data-k-material`/`data-k-backdrop` (set by `applyTheme`, or `themeToAttrs` for subtrees) and `styles/material.css`; surfaces opt in with `data-k-surface` or a `dialog/menu/listbox` role. Density, motion and named font sizes work by `tailwind/preset.cjs` wrapping Tailwind's spacing/duration/fontSize scales in `calc(… * var(--k-…))`, so arbitrary values (`px-[10px]`) don't scale. `border.width`, `focus`, `selection` and `backdropMotion` follow the same opt-in pattern: tokens always emitted (defaults in `tokens.css`), behaviour only when the theme sets them (`data-k-focus`, `data-k-selection`, `data-k-backdrop-motion`). `src/theme/export.ts` serializes/imports themes; `stories/ThemeEditor.stories.tsx` is the live editor.

**Physical motion** (`src/motion`, no deps). `spring.ts` is the closed-form damped spring (`springAt`, `spring({bounce,duration})`, `springToLinear` → CSS `linear()` + settle duration, validated against RK4 in `scripts/motion.test.cjs`). Hybrid: open/close/indicators are pure CSS transitions on theme vars `--k-spring-<role>[-duration]` (roles `enter|exit|pop|move|gesture`, characters `sober|smooth|expressive|playful` in `presets.ts`, resolved in `theme/tokens.ts`, all with sober-like `var()` fallbacks and a `@supports not linear()` cubic fallback); JS rAF springs only for gestures (`useSpring`, `useDragDismiss` with velocity continuity, writing the `translate` property so it composes with `transform` classes). Pattern: component sets `data-state="open|closed"` and keeps itself mounted for the exit (`useAnimatedPresence`, `usePopover.mounted/popoverProps`); classes `k-appear`/`k-sheet`/`k-scrim`/`k-indicator`/`k-stagger` live in `styles/motion.css`. Changing characters/defaults means mirroring `styles/tokens.css` (`check-tokens`). Probe: `scripts/probe-motion.cjs`.

**Animation API** (`src/motion`, on top of the springs; no component in `src/components`, `src/ai` or `src/chat` may import it). Pure: `values.ts` (parse, align units, interpolate; colors in OKLab), `drivers.ts` (spring, timing, keyframes and repeat as functions of time), `motionState.ts` (state priority, `initial` to CSS), `scrollProgress`, `constrainDrag`/`releaseTarget`; tested in `scripts/motion-api.test.cjs`. Engine: `frameloop.ts` (one rAF for everything, off when idle), `elementWriter.ts` (`x`/`y`/`z`/`inlineX`/`layoutX`/`layoutY` compose into `translate`, likewise `scale` and `rotate`, so Tailwind `transform`s survive), `animate.ts` (one owner per property and element: a new animation takes over that property only and inherits value and velocity; the last frame writes the value as requested, so a `var()` keeps following the theme). React: `Motion.tsx` (never rerenders per frame; the first-render `style` is frozen so React can't overwrite animated values), `Presence.tsx`, `motionHooks.ts`, `useScroll.ts`, `drag.ts`, `layout.ts`. Named effects are a registry (`motionPresets.ts`). Docs in `docs/movimiento.md`, story **Animar**, probe `scripts/probe-motion-api.cjs`.

**Gestures** (`src/gestures`, no deps, exported from the main entry). `recognizer.ts` is a pure state machine (`createGestureRecognizer(options, emit)`: feed `down/move/up/cancel` pointers, call `tick(now)` when `pendingAt` says so; emits tap/doubleTap/longPress/swipe/pan/pinch; tested in `scripts/gestures.test.cjs`). `useGestures` binds it to pointer events (capture during pan/pinch, long-press timer, haptics, `data-gesture` attribute, `style.touchAction` from `touchActionFor`); defaults to touch+pen only and ignores `GESTURE_IGNORE` targets. `useSwipeAction` = `useGestures` + `useSpring` for "slide to act and come back" (writes `translate`, `--k-swipe` and `data-swipe` on `progressRef`/the element; rubberband past `distance`, returns with the theme `gesture` spring). Chat's `useChatMessageGestures` is a thin wrapper; `useDragDismiss`, `BottomSheet` and `TileMap` keep their own tuned pointer code. Prefer these hooks over new ad-hoc pointer handlers. Browser probes: `scripts/probe-gestures.cjs` (story **Gestos**) and `scripts/probe-chat-touch.cjs`.

**Map** (`src/map`): `geo.ts` is pure Web Mercator maths (`project`, `visibleTiles`, `fitBounds`, `clusterPoints`; unit-tested in `scripts/map.test.cjs`, exported as the `mapGeo` namespace to avoid generic names). `Map.tsx` (`TileMap`) owns the view state, gestures (pointer/pinch/wheel/inertia) and tiles (two zoom levels stacked so loading gaps show the parent); `Layers.tsx` has `Marker`, `MapPopup`, `MarkerCluster`, `MapPath`, `MapCircle` positioned through `useMap().toScreen`. Map styles are a registry (`styles.ts`, `registerMapStyle`; built-ins are OSM + CSS filters so none needs an API key), geocoders are plain functions (`geocode.ts`), and `MapControl` portals into the four corner containers the map exposes through context (their callback refs must stay stable or React loops). Styles in `styles/map.css`. Never hardcode a tile provider's key in the library: `tileUrl` is a prop.

**Controls and panels.** Slider, Rating, OtpInput, ToggleGroup, InlineEdit, ChoiceCards, SignaturePad, SplitPane, ScrollArea, VirtualList, TreeView and BottomSheet keep their maths in pure helpers under `src/components/internal/{slider,otp,split,snap,tree,virtual}.ts` (tested in `scripts/controls.test.cjs`, which also checks their server markup/ARIA), and share label/description wiring through `internal/ControlField.tsx`. Styles live in `styles/controls.css` and `styles/layout.css`. Browser probe: `scripts/probe-controls.cjs`; `VirtualList` measuring (rows unmounted by scrolling must not be recorded as 0 px; scroll is anchored when heights above change) has its own `scripts/probe-virtual-list.cjs`. `BottomSheet` is the single mobile sheet: `Modal` delegates to it when narrow and its presentation is `sheet` (so every `adaptivePortal`/`MobileOverlay` menu, select and date picker gets it), and `Drawer` does too with `mobilePresentation="sheet"`; in that branch Modal/Drawer skip their own scroll lock, focus trap and Escape (the sheet owns them). Probe: `scripts/probe-mobile-sheets.cjs`.

**Shared internals (reuse before writing a new helper).** `src/internal/`: `text.ts` (`fold` accent-insensitive compare, `matchesAllWords`, `foldedRange`/`foldedRanges` for highlighting, `escapeRegExp`), `intl.ts` (`DEFAULT_LOCALE`, cached `getNumberFormat`/`formatNumber`), `format.ts` (`formatBytes`, `formatTimeOfDay`, `formatClock`), `files.ts` (`matchesAccept`), `url.ts` (`safeUrl` link/media/attachment), `storage.ts` (`safeStorage`, `useRecentSearches`), `roving.ts` (`rovingNext` arrow-key groups), `pointerDrag.ts` (`startPointerDrag`, `isPrimaryPointer`), `escapeStack.ts` (Escape closes only the top layer — popovers and menus use it too). `src/hooks/`: `useResizeObserver`/`useElementSize`, `useMergedRefs`, `useCopyToClipboard`/`copyText`, `useObjectUrl`, `useAutosize`, `useIsMobile` (`MOBILE_MAX = 768`, the same cut as `styles/mobile.css`). `motion/dom.ts`: `afterNextPaint` (cancellable double rAF) and `exitDelay`. Labelled controls render through `components/internal/ControlField.tsx` (+ `describedBy`). Anything shared by `src/ai` and `src/chat` must live in `src/internal`/`src/hooks`, never in `src/ai` (the main entry must not import `./ai`). «No motion» is one rule in `styles/motion.css` (`--k-motion: 0` under reduced motion or `data-motion="off"`): every duration must multiply by `--k-motion` (enforced by `check-motion`; the preset also scales Tailwind's `animate-spin/pulse/ping/bounce`; JS animations use `motion/dom.ts` `motionDisabled`/`readMotionSpeed`, and `motionDisabled` is also true when the theme speed is 0).

**Dates, gallery, guides, showcase.** Calendar maths for `DateRangePicker`, `HeatmapCalendar` and `Countdown` is pure in `components/internal/calendar.ts` (ISO strings compared as text, days added at local noon so DST never skips a day); `TimePicker` exports `parseTime`. Their styles are in `styles/extras.css`. Story images come from `stories/shared/demoImages.ts` (generated SVG, no network). Probe: `scripts/probe-extras.cjs`.

**Calendar, Kanban, Table.** Pure maths lives in `components/internal/schedule.ts` (overlap columns, all-day lanes, drag-to-create ranges, keyboard nudges), `internal/kanban.ts` (lane↔column index, drop index correction, due states, keyboard targets) and `internal/tableFilters.ts` (filter matching/chips, accent-insensitive search, aggregates, `pageItems` for `Pagination`), all tested in `scripts/schedule.test.cjs`. Styles: `styles/calendar.css`, `styles/kanban.css`, `styles/table.css`. Event/card/label colors travel as CSS vars (`--k-ev`, `--k-kb-tone`, `--k-kb-tag`) so `soft` styles tint with `color-mix` and keep theme text. Kanban grid items carry explicit `gridColumn` (collapsed columns must keep their track or everything shifts). The Kanban drag clone is portaled to `body` and positioned by writing `transform` directly; tilt is a `useSpring`. Probes: `probe-calendar.cjs`, `probe-kanban.cjs`, `probe-table.cjs` (plus the older `probe-tablero.mjs`, `check-erp.mjs`, `check-data-entry.mjs` for tables; the `.mjs` checks need `CHROME_PATH`).

**Expressive pieces.** `components/TextFx.tsx` (text effects), `Prose.tsx` (long-form text, reading), `Microinteractions.tsx` (`pop`, `flyTo`, `BurstToggle`, `HoldToConfirm`…); styles for these plus the newer Gantt/Kanban behaviour in `styles/expressive.css`. `hooks/useInView` and `motion/useFlip` (FLIP on `translate`, resumes in-flight animations, positions measured against the root's content so scroll isn't movement) are shared. `HoldToConfirm`'s hold time is deliberately not scaled by `--k-motion`: it is a safeguard, not decoration. Gantt maths is pure in `components/internal/gantt.ts` (tested in `scripts/schedule.test.cjs`). Kanban: `onCardMove` fires on release, never delayed by the landing animation; the copy flies over the real card, which stays hidden (`data-arriving`) until it lands. Touch pick-up is long-press (the `touchmove` blocker must be registered before the gesture starts, or the browser won't let it cancel scrolling). Probe: `scripts/probe-expressive.cjs`.

**Icons.** The library is icon-library agnostic. Components never import an icon library: the UI renders `<UiIcon slot="chevron-down" />` (`ICON_SLOTS`, internal roles) and users write `<Icon name="…" />` with the names of THEIR library (`FiHome`, `HouseIcon`, `mdi:home`). An `IconLibrary` is `{ resolve(name), slots }`; `slots` says what fills each UI role. Lookup order: nearest `IconProvider` → registered libraries (`registerIconLibrary`, last wins) → Lucide (`src/icons/lucide.ts`, the only file allowed to import `lucide-react`; enforced by `scripts/check-icons.mjs`; it bundles only the icons the UI uses). Factories: `iconLibraryFromModule` (auto-detects naming + fills slots via `ICON_ALIASES`), `iconLibraryFromIcons`, `iconLibraryFromResolver`. Adding a UI icon = add the slot to `slots.ts`, its aliases to `aliases.ts` and its Lucide filler to `lucide.ts`.

**Translations** (`src/i18n`, exported from the main entry). Every user-visible string (JSX text, `aria-*`, `title`, `placeholder`, default `*Label`/`*Message` props, month/day words) comes from the catalog `esMessages`, split by namespace in `src/i18n/catalog/*.ts` (`common`, `dates`, one namespace per component, `table`, `calendar`, `kanban`, `chat`, `map`, `ai`…). Spanish is the only built-in language and the fallback; apps add languages with `registerTranslations(locale, partialMessages)` (registry like icons/themes, `fr-CA → fr → es` fallback, validated on register) and pick one with `I18nProvider locale` (optional, nestable; `messages` overrides a subtree) or `setDefaultTranslationLocale`. Values are JSON-friendly: strings with `{vars}`, plural objects `{ one, other, … }` with `#` (resolved with `Intl.PluralRules`), string arrays. Components read `useI18n()` (`messages`, `format`, typed `t('ns.key', vars)`) or `useMessages('ns')`; an existing prop always wins (`label ?? m.key`), and catalog hooks must be called unconditionally (never `prop ?? useMessages()`). Pure helpers take the words as a parameter defaulting to `esMessages` (`dueLabel`, `describeFilter`, `rangePresets`, `fechaRelativa`, `chatDate`, `chatFileType`). Only words are translated: number/currency formats keep `DEFAULT_LOCALE`/the `locale` prop. `src/ai/labels.ts` aliases the `ai` namespace (`useAILabels(labels)` = catalog + prop). Checks: `scripts/check-i18n.mjs` (literals), `scripts/i18n-pseudo.test.cjs` (SSR in the `pseudoMessages()` locale, every text must be wrapped in ⟦…⟧), `scripts/probe-i18n.cjs` (every story with `?k-locale=pseudo`, which `.ladle/components.tsx` honours). `npm run i18n:template -- es.json` exports the catalog for translators. Story: `stories/Traducciones.stories.tsx`.

**Customization contract.** Everything that lists options shares `components/internal/optionStyle.ts`: `ItemRenderState` (`selected`, `highlighted`, `disabled`, `query`, `label`, `content` = the default rendering), `ItemClassName`, `SelectedStyle`, `optionRowClass`. Naming is fixed: `renderOption`/`optionClassName` for option-like controls, `renderItem`/`itemClassName` for menus and lists (`MenuItemButton` carries it for all menus). Rendering only replaces content: role, keyboard, search and a11y stay in the component. `context/ComponentDefaults.tsx` gives props defaults per component type (`useComponentDefaults(name, rawProps)`; explicit prop wins, `undefined` doesn't override); a new option-like component must adopt both. Navigation, status and data components (`Tabs`, `Accordion`, `Stepper`, `Timeline`, `Breadcrumbs`, `NotificationList`, `TreeView`, `Calendar`, `Table`, `ToastProvider`) follow the same idea with their own context. Probes: `scripts/probe-customization.cjs`, `scripts/probe-customization-more.cjs`.

**Table** is split under `components/table/`: `types.ts`, `parts.tsx`, `useTableData.ts` (filter/search/sort/page), `useColumnLayout.ts` (resize, sticky), `TableToolbar.tsx`, `TableCards.tsx`.

**AI response.** `AIMarkdown` renders per block (`ai/internal/markdownStream.ts`: `splitMarkdownBlocks` must keep the same output as the whole text, tested against a corpus in `scripts/ai.test.cjs`; with reference definitions it keeps the text whole) and `closeIncompleteMarkdown` repairs only the last block while `streaming`. Tool presentation is a registry (`ai/toolViews.tsx`, `registerToolView(name, view)`, `*` as fallback, `ToolViewBoundary` falls back to raw JSON). Consecutive `tool` parts group in `AIToolGroup` unless `groupTools={false}` or `renderPart` is set. `AIQuestion` is both a message part and standalone. `AIMessageCustomization` is exposed through `AIConversation messageProps`, `AIWorkspace conversationProps` and `ComponentDefaults`; `src/ai` adds its keys to `ComponentDefaultsMap` by module augmentation, because the main entry must not import `./ai`. `remarkCitations` turns `[n]` into `ai-cite` (never inside code or links; unknown numbers stay literal). `AISelectionAction` and swipe-to-quote need `onQuote`; `AIWorkspace` supplies a default. Long press is off by default because on touch it would disable native text selection, which quoting depends on. Long conversations use `content-visibility` (over 40 messages), not unmounting, so local state survives; containment is dropped on hover/focus so citation cards aren't clipped. Probe: `scripts/probe-ai-response.cjs`.

**Registries over constants.** Catalogs are open for plugins: `registry.ts` (`registerThemePreset`, `registerTokens`, `unregisterThemeSource`, validated on register) and `useThemePresets` for reactive reads. `CodeEditor` likewise accepts custom languages (`CodeLanguageDefinition`) and themes. Custom message content follows the same shape in both messaging modules: AI `registerMessagePart(kind, render)` (`src/ai/partRegistry.tsx`) and chat `registerChatBlock(kind, render, { summary, fill })` (`src/chat/blocks.tsx`; `ChatProvider blockRenderers` wins over the registry, messages carry serializable `blocks: [{ kind, data }]`, `useChatMessageText` gives previews/search the block `summary` when `text` is empty, an error boundary isolates failing blocks). When adding a catalog, make it a registry, not a closed constant.

**Charts palette** (`src/charts/palette.ts`): slot order was chosen by a palette validator (incl. color-blind separation, light and dark); don't reorder by eye. Series colors are assigned in order without cycling; semantic roles (`positive`, `negative`, `warning`, `neutral`) are reserved.

**CodeEditor** (`src/components/CodeEditor.tsx` + `src/components/code-editor/`): native `textarea` overlaid on own lexical highlighting, no third-party engine. Pure editing logic (`editing.ts`), tokenizers (`languages.ts`), themes (`themes.ts`), virtualized rendering of visible lines (`CodeHighlight.tsx`), optional animated caret/selection (`CodeMotion.tsx`). Keep editing logic pure so it stays unit-testable.

**Overlays/infra**: shared hooks in `src/hooks` (`usePopover`, `useFocusTrap`, `useScrollLock`, `useAnimatedPresence`), Escape handling via `src/internal/escapeStack.ts`, global providers in `src/context` (Toast, Popup, Theme). `.ladle/components.tsx` wraps every story in `MemoryRouter` + `ToastProvider` + `PopupProvider` and toggles `.dark`.

**Right to left.** `dir="rtl"` works through logical properties, so never write `ml-`, `pr-`, `left-`, `text-left`, `border-l`, `padding-left` or `left:` for something that should mirror: use `ms-`, `pe-`, `start-`, `text-start`, `border-s`, `padding-inline-start`, `inset-inline-start`. `styles/rtl.css` holds the exceptions: components with their own axis stay LTR, directional icons flip through `data-k-flip` (`DIRECTIONAL_SLOTS` in `icons/Icon.tsx`). Pointer maths on `clientX` needs the sign of `direction`. Probe: `scripts/probe-rtl.cjs`.

**Docs.** `README.md` is an index; each area has its own file under `docs/` (Spanish). `CHANGELOG.md` is updated with every user-visible change.

## Conventions

- One Ladle story file per component in `stories/` (root, not next to components).
- Library components wrap native controls; elsewhere use `Select`/`SearchableSelect`, `Textarea`, `DatePicker` (enforced by `check-nativos`).
- No hardcoded Tailwind palette colors or hex outside a `var()` fallback (enforced by `check-hardcoded-colors`).
- Contrast target is WCAG AA (4.5:1 text, 3:1 large); theme registration warns on failures.
- No visible text written in a component: add it to `src/i18n/catalog` (Spanish) and read it with `useI18n`/`useMessages` (enforced by `check-i18n`).
- Everything follows the theme, not only colors (enforced by `check-theme-scale`):
  - Font sizes in CSS are `calc(13px * var(--k-text-scale, 1))`; in Tailwind use a preset size or `text-[length:calc(13px*var(--k-text-scale,1))]`, never `text-[13px]`.
  - 1px borders are `var(--k-border-width, 1px) solid …`.
  - Titles use `font-display`.
  - Structural padding multiplies by `--k-density`.
  - Exceptions: rows with a fixed JS height (CodeEditor's 22px lines, so its text caps at `min(16px, …)`); mobile inputs stay at ≥16px (`max(16px, …)`) so iOS doesn't zoom.
